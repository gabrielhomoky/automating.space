# HANDOFF — automating.hu SEO / AEO / GEO optimization (2026-08-23)

## What was changed

A build-time enhancement layer (`tools/seo/enhance.mjs`) now runs automatically
after `node build-site.mjs`, on top of the assembled `site-deploy/` output.
Source HTML stays the design's source of truth — the enhancer only adds
machine-facing layers and delivery optimizations. Verified with a full-page
pixel diff against production: 4,607 differing px out of 5.46M, all inside the
hero button's 1px animation-phase jitter. No visible design, copy, or UX change.

Changes fall into four groups:

1. **International / crawlability** — hreflang (hu/en/x-default) on every
   paired page; two new pre-rendered pages, `/en` and `/case-studies-en`,
   generated from the existing client-side `T.en` translation dictionaries (so
   English visitors and crawlers get real server HTML, not a JS-only switch);
   sitemap grew from 10 to 17 URLs with `xhtml:alternate` links and `lastmod`.
2. **Entity / structured data** — `Organization` schema enriched with the
   imprint's public legal data (legal name, address, phone, VAT ID,
   registration number, chamber membership), `sameAs` to 4 verified external
   profiles, founders as `Person` entities, `knowsAbout` linked to
   Wikipedia/Wikidata, and `about`/`mentions`/`speakable` added to every page.
3. **Machine access** — `robots.txt` explicitly allows 22 named AI/search
   crawlers; `llms.txt` rewritten (dead `.html` links fixed) plus a new
   `llms-full.txt` full-text corpus; every article and top-level page now has
   a `.md` alternate (`<link rel="alternate" type="text/markdown">`); an
   IndexNow key was generated and all 17 sitemap URLs submitted (HTTP 202).
4. **Performance** — Inter self-hosted as a variable font instanced down to
   weights 400–600 (48+85 KB → 35+58 KB), only the latin subset preloaded;
   `consent.css` inlined; inline CSS/JS minified with esbuild; the large
   per-page inline `<script>` externalized to a deferred file; a no-op guard
   added to `setLang()`'s `innerHTML` writes (was repainting the hero and
   delaying LCP on every language switch, including the initial one).

Plus small source-level fixes: EN meta descriptions trimmed to ≤160 chars,
stale `.html` URLs cleaned out of JSON-LD, impresszum's duplicate `<h1>` fixed
to `<h2>`, `blog-en.html`'s title made unique, `assets/fonts/` added.

## Known limitations

- **GEO score (70.7) is below AEO/SEO** because three of its four categories
  depend on facts outside this codebase's control: Google/Bing index
  presence, third-party citation count, and Wikidata/Wikipedia presence. The
  schema and content-side levers available in the repo are essentially
  maxed out; further GEO gains come from the manual tasks above, not more code.
- **Facebook was deliberately excluded** from `sameAs` — the URL returns a
  generic 200 "Facebook" title with no page confirmed to exist, so it wasn't
  treated as verified. Flagged in `external.json` rather than silently guessed.
- **Bing sitemap ping returns 410** — Bing deprecated the ping-based sitemap
  submission endpoint sometime before this audit; this is expected and not
  something to "fix." IndexNow is the current mechanism and is working (202).
- **Google/Bing index counts in `external.json` are point-in-time browser
  observations** (2026-08-23), not a live API — they will drift and should be
  re-checked periodically, especially after the Bing WMT step above.
- **Lighthouse performance (88) has run-to-run variance** (observed 85–90
  across 3 runs) — typical for mobile CPU-throttled runs; the reported number
  is the median, not a guaranteed floor.
- The `assets/fonts/*.woff2` files are pre-built and committed rather than
  generated at build time — regenerating them requires `fonttools`
  (Python) with the `instancer` module, which isn't part of this repo's
  normal toolchain (see commit history for the one-off script used).
